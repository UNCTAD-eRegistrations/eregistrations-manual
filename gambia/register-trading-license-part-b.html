1. Workflow Overview

Applications for KMC Trading Licenses move through six desks in a fixed sequence. Three desks are operated by KMC officers (Review, Approval, Payment), two by automation bots (Registration, Certificate), and the Applicant role handles the feedback loop when corrections are requested.

2. Desk 1 — KMC Review

1

KMC Review

UserRole · start role · sort order 0 · visible to applicant
UserRole Start Sort 0

What arrives at this desk

A freshly submitted application from a citizen. The file contains the License Owner, Business Details, and License Details tabs filled by the applicant, along with the uploaded ID and TIN documents. This is the first officer-handled desk in the workflow.

What you do here

As a KMC Review officer you must:

  1. Open the file and read the applicant's three tabs end-to-end.
  2. Cross-check the declared activities against KMC records and any inspection notes.
  3. Confirm the business address falls within the KMC jurisdiction.
  4. For each row in the Trading Licence grid, look up the schedule fee and record any multiplier.
  5. Capture inspection details (date, zone) if a site inspection was carried out.
  6. Write a comment for the approving officer summarising your findings.
  7. Click Validate application to forward to KMC Approval, or send back / reject if needed.

Available actions & destinations

StatusNext deskWhen to use
FILE VALIDATED KMC Approval Declaration is accurate, fees are correctly computed, recommend approval.
FILE PENDING (stays at Review) Default state — while you investigate or wait on inspection. Do not leave files in this state for long.
SEND BACK TO CORRECTIONS Applicant Declaration is incomplete or inconsistent; ask the applicant to amend & resubmit.
FILE REJECT Applicant Application is not eligible (wrong jurisdiction, fraudulent declaration, etc.).

Attached automations on this desk

  • FORM copy — sectors and activities to KMC Review — internal bot that copies the applicant’s declared activity grid into the reviewer’s editable grid when the file lands at this desk.
  • KMC FEES read fee and multiplier — Review — data bot reading from the GDB KMC FEES (1.7) database to pre-populate schedule fees and multipliers for each declared activity.
  • NATURAL PERSONS read owners registered ID and email and address — data bot reading from the GDB NATURAL PERSONS (6.9) database to cross-check the applicant’s ID, email and address against existing records.
  • v-RIGHTS read business details — data bot reading from VIEW-RIGHTS to confirm which businesses the applicant is authorised to act for.
  • KMC Report display — document bot that generates a printable inspection report on demand (the “Template report” button).
Reviewer tips
  • Always confirm the business address is within KMC before validating — if it’s in Banjul or Brikama, reject with a clear note.
  • If a declared count seems implausible (e.g. 200 rooms for a residential address), trigger a site inspection and use Send Back to Corrections rather than guessing.
  • Use the “Comment for approving officer” field generously — it’s the only context the next desk sees.
  • The fee calculation panel auto-fills from the KMC FEES bot, but you can override if a special arrangement applies. Document any override in the comment.

3. Desk 2 — KMC Approval

2

KMC Approval

UserRole · sort order 1 · visible to applicant
UserRole Sort 1

What arrives at this desk

Files validated by the KMC Review officer. You see the full declaration, the reviewer’s computed fees, their inspection notes, and their comment.

What you do here

As a KMC Approval officer:

  1. Re-check the activity grid and fees prepared by the reviewer.
  2. Validate the total cost computation against the KMC schedule.
  3. Decide whether to issue an invoice (Issue invoice? = Yes) or hold (Yes/No).
  4. Generate the invoice number and pick the invoice issue / due dates.
  5. Click Validate application to forward to KMC Payment, or send back to Review for corrections.

Available actions & destinations

StatusNext deskWhen to use
FILE VALIDATED KMC Payment Invoice issued, fees confirmed. Send to applicant to pay.
SEND BACK TO CORRECTIONS KMC Review (internal loop) Reviewer made a mistake in the activity grid or fee calculation. Sends back to Review — not to the applicant.
FILE REJECT Applicant Application has substantive issues that cannot be fixed by Review (e.g. ineligibility detected at this level).
FILE PENDING (stays here) Default state during your review. Do not leave files in this state for long.

Attached automations on this desk

  • KMC REVIEW copy — sectors and activities to KMC Approval — internal bot that copies the Review’s validated activity grid into the Approval form so you don’t re-enter it.
  • KMC FEES read fee and multiplier — Approval — data bot re-reading the KMC FEES database to confirm schedule values at the Approval stage.
  • KMC Invoice display — document bot that generates the printable invoice PDF when you click “Print invoice”.
  • KMC APPROVAL send — corrected sectors and activities to KMC Review — internal bot that pushes corrected activity rows back to Review when you click “Send back to corrections”.
  • KMC APPROVAL copy — sent back for corrections — internal bot that sets the “sent back for corrections” flag visible on the Applicant side.
  • KMC Report 2 display — document bot for an alternative inspection report template.
Approval tips
  • You can override fee values directly on the Approval form if the reviewer applied the wrong schedule row — document why in the comment.
  • Setting Issue invoice = Yes unlocks the invoice number / dates and triggers the KMC Invoice display bot. Issue invoice = No holds the file.
  • If you spot a calculation error, prefer SEND BACK TO CORRECTIONS (internal loop to Review) over FILE REJECT — that way the applicant doesn’t lose time.

4. Desk 3 — KMC Payment

3

KMC Payment

UserRole · sort order 2 · visible to applicant
UserRole Sort 2

What arrives at this desk

An approved file with an issued invoice. The applicant sees the invoice on their dashboard and pays through the portal. As a Payment officer your role is to confirm each instalment payment and validate the file once the invoice is fully paid.

What you do here

  1. For each instalment payment, the system records it in the “KMC payments” grid with a Payment N°, date, amount paid, and remaining balance.
  2. Click Confirm payment on each instalment row to mark it as received.
  3. When the remaining balance reaches zero, the “Fully paid” checkbox auto-ticks. Capture the issued / renewal dates and license number.
  4. Click Validate application — this triggers the automated registration step.

Available actions & destinations

Attached automations on this desk

  • KMC PAYMENTS save payment instalments — KMC Payment — data bot writing each instalment to GDB KMC PAYMENTS (1.9).
  • KMC PAYMENTS copy — amount paid — internal bot that propagates the running total into the totals panel.
  • KMC PAYMENTS copy — 1st payment date to license issued date — internal bot that initialises the license “Issued” date from the first instalment.
  • FORM copy — license details to certificates — internal bot that copies the activity grid into the Part A “License details from KMC Approval after invoice is fully paid” section visible to the applicant.
Payment desk tips
  • Don’t click Validate application until the “Total remaining” field is exactly zero. If you forward early, the registration bot will fail.
  • Each instalment amount must be less than or equal to the remaining balance — the form enforces this rule. Reject overpayments and ask for a refund instead.
  • If a payment has been received but the amount looks wrong, contact KMC Finance before confirming — once confirmed it’s recorded in GDB.

5. Desk 4 — KMC Registration (automated)

4

KMC Registration

BotRole · sort order 3 · not visible to applicant
BotRole Sort 3

What this desk does

This is the first of two automated desks. No human form — just a chain of data bots that write the licence into the registry databases and link it to the applicant’s rights records. It runs automatically as soon as KMC Payment validates a fully-paid file.

Bots that run, in order

#BotActionTarget GDB database
1 NATURAL PERSONS create or update — representative Create / update NATURAL PERSONS (6.9)
2 TRADING LICENSE PAYMENTS create or update Create / update TRADING LICENSE FEES (4.4)
3 TRADING LICENSES create Create the licence entry TRADING LICENSES (6.6)
4 RIGHTS create trading licence relations — applicant Create rights entry RELATIONS RIGHTS (5.1)
5 RIGHTS create trading license relations — representative Create rights entry RELATIONS RIGHTS (5.1)
6 TRADING LICENSE PAYMENTS update entries with license nr Update payment entries with the new licence N° TRADING LICENSE FEES (4.4)

Conditional execution

Bot #1 (representative create/update) only runs when the application was submitted by someone other than the owner — gated on the determinant “Application for someone else”. Bot #5 (representative rights) is similarly gated. If the applicant submitted for themselves, those two bots are skipped.

Available statuses

StatusNext deskMeaning
FILE VALIDATED KMC Certificate (bot) All bots completed successfully. Licence is now in the registry.
FILE PENDING (stays here briefly) Bot chain in progress — typically seconds.
Bot failed (paused for support) One of the bots returned an error (GDB unavailable, schema mismatch, etc.). Escalate to support.
What to do if “Bot failed”

Open the application’s audit log to see which bot failed and why. The most common causes are: (a) GDB connectivity issue — retry the bot from the audit panel; (b) missing required field on the applicant data — send the file back to KMC Payment with a note; (c) duplicate license number — have the Payment officer regenerate the license N° before retrying.

KMC Certificate

What this desk does

The final automated step. A single document bot generates the signed KMC Trading License Certificate PDF and uploads it to the applicant’s file. After this runs, the application is complete — the applicant can download the certificate from their dashboard.

Bot that runs

Available statuses

StatusEffect
FILE VALIDATED Certificate uploaded. Application reaches final state. Applicant is notified.
FILE PENDING PDF generation in progress (typically seconds).
Bot failed PDF generator returned an error. Escalate to support — usually a template issue or a missing data field.
Template-driven content

The certificate template includes all 13 activity-row variants (Per room, Per truck, Per machine, Per booth, Per show, Per premise, Per boat, Per cold store, Per borehole, Per billboard, Per vehicle, Per CU M³, Per plant) so the PDF renders correctly regardless of the activities declared. Each variant is driven by a corresponding determinant tagged “(generated by copying)” in the determinant list.

7. Desk 6 — Applicant (feedback loop)

6

Applicant

UserRole · sort order 299 · visible to applicant
UserRole Sort 299

When the file lands here

The Applicant role receives files routed back from KMC Review, KMC Approval (only for rejects), or KMC Payment via the SEND BACK TO CORRECTIONS / FILE REJECT statuses. The applicant sees the officer’s comment and the “Sent back for corrections — KMC Approval” flag on their Part A form.

What the applicant does

  • Opens the application from the dashboard.
  • Reads the officer comment (rendered on a prominent banner).
  • Edits the relevant tab(s) and re-uploads documents if requested.
  • Re-submits, which routes the file back to KMC Review.

Available statuses

StatusEffect
FILE PENDINGDefault while the applicant prepares the corrections.
FILE VALIDATEDResubmission — file moves back to KMC Review.
Internal flags

Two hidden text fields drive the loop logic: applicantSentBackForCorrectionsKmcReview on Part A (toggled when Approval sends back), and the comment fields kmcReviewCommentForApprovingOfficer / kmcApprovalCommentForApprovingOfficer on the officer forms. These are written by internal bots when the SEND BACK action is taken.

Stock value bands (for retail categories)

Six numeric bands per desk (Review & Approval) drive how the stock-value tariff is applied:

  • Stock value = 0 — no stock declared, no stock-based fee.
  • Stock value > 0 — some stock declared, triggers stock-based logic.
  • <= 100,000 GMD — lowest band.
  • > 100,000 GMD — above lowest band.
  • <= 200,000 GMD — mid band.
  • > 200,000 GMD — highest band.

10. Officer Tips & Escalation

General principles

  • Always read the previous desk’s comment before validating — many errors are caught by following the trail upstream.
  • Use SEND BACK TO CORRECTIONS in preference to FILE REJECT when the issue is fixable — reject is for substantive ineligibility.
  • Don’t click Validate at KMC Payment until “Total remaining” is exactly zero. Forwarding early triggers a bot failure at KMC Registration.
  • The activity grid auto-fills via internal copy bots, but any field can be overridden. When you override, leave a comment explaining why.
  • Print the inspection report and the invoice for the case file even though the PDFs are stored digitally — useful for KMC archive and disputes.

When to escalate

SituationEscalate to
Bot failed status at KMC Registration or CertificateGambia Easy Business technical support, with the application reference and audit log.
GDB lookup mismatch — the BR / TIN exists but doesn’t match the applicantRGD or GRA liaison — do not validate the file until resolved.
Applicant claims overcharging on the schedule feeKMC Trading Licenses Unit head — you can hold the file at Payment while clarification is sought.
Duplicate license number suggested by Registration botHave the Payment officer regenerate the License N° from the role form and retry.
Suspected fraudulent declaration (e.g. wrong jurisdiction claimed)Reject the file with a clear reason and refer to KMC Enforcement.
