1. Service Overview

The File Annual Report service on the Lesotho OBFC eRegistrations platform allows registered companies to submit their annual financial statements and update company records electronically. It covers two registrations:

  • Annual Filing — The citizen uploads financial statements for one or more pending fiscal years.
  • Update of Data — The citizen updates company contact/address information in the registry without filing financial statements.
How the system loads data

When a citizen opens the service, several bots run automatically in the background: vRIGHTS list retrieves companies linked to the user, COMPANIES read fetches the company’s current registry data, and ACCOUNTS list loads the list of fiscal years with their filing status (due or completed). The citizen sees this data pre-filled in the form — they do not need to enter it manually.

Documents generated by the service

Document Bot When generated
Application Form APPLICATION FORM display On submission — displays the filled application form as a PDF for officer review.
Extract of Companies Registry EXTRACT OF COMPANIES REGISTRY upload After COMPANIES database update — generated and attached to the application.
Filing Notice FILING NOTICE upload After ACCOUNTS database update — generated and attached to confirm the filing.

Parallel registrations

An Annual Filing submission triggers both the COMPANIES and ACCOUNTS bot roles sequentially. An Update of Data submission (contact/address only) also goes through Review Filing and the COMPANIES database bot, but does not require a financial statement upload.

3. Type of Roles

There are two types of roles in an eRegistrations service:

Assigned to a government officer who manually reviews or processes an application. The officer sees the application form, can add comments, and sets a status to move the file forward or send it back to the citizen.

Role Statuses

Status Meaning Next step
FILE PENDING Application is queued and awaiting officer action. No action required unless it stalls for more than 24 hours.
FILE VALIDATED Officer approved the application. Moves to the next role. System automatically triggers the COMPANIES database bot.
SEND BACK TO CORRECTIONS Application returned to the citizen with comments for correction. Citizen must correct and resubmit. File returns to Review Filing.
FILE REJECT Application permanently rejected. No further processing. Citizen is notified. No action required from officer.

Executed automatically by the system — no officer action is required. Bots perform tasks such as updating a government database or generating certificate PDFs. They run sequentially after the previous step succeeds.

Bot Statuses

Status Meaning Action Required
FILE PENDING Bot is queued or running. None. Monitor if still pending after 30 minutes.
FILE VALIDATED Bot ran successfully; database updated or document generated. None — the next role starts automatically.
BOT FAILED Bot encountered an error during execution. File is routed to the corresponding PROBLEM role for manual resolution.

4. Description of Roles

Review Filing

Human role — OBFC Processing Officer

Step 1

This is the first and only human role in the service. An OBFC processing officer reviews the citizen’s submission: the completed form, the uploaded financial statements for each fiscal year, and the company information. The officer verifies that the filing is complete and the documents are valid.

What to check

  1. 1

    Verify company identity

    Confirm the filing is for the correct company. Check the company name, registration number (Business ID), and legal type against the registry.

  2. 2

    Check financial statements for each year

    For each year listed in the Filings Due grid, verify that a financial statement document has been uploaded. Open and review each attachment to confirm it is legible and corresponds to the declared year.

  3. 3

    Check Update of Data fields (if applicable)

    If the citizen also updated contact or address information, verify that the new district, town, email, and phone values are plausible and complete.

  4. 4

    Set status

    Approve: Set status to FILE VALIDATED. The system triggers the COMPANIES database bot automatically.

    Send back: Set status to SEND BACK TO CORRECTIONS with a clear comment explaining what needs to be corrected (e.g., missing statement for year X, illegible document).

    Reject: Set status to FILE REJECT only for fraudulent or fundamentally invalid applications.

Multiple years

A single application can contain financial statements for multiple years. Each year must have its own uploaded document. If any year is missing its document, send the entire application back for corrections.

Register in COMPANIES database

Automated bot role — runs after officer approval

Step 2

This bot role runs automatically once the officer sets FILE VALIDATED. It updates the company’s records in the government GDB (General Database) and generates the Extract of Companies Registry document.

Bots in this role

  1. 1

    LEGAL PERSON - update (Main office address)

    Updates the main office address for the legal person record in the GDB. Runs if the citizen submitted an Update of Data with new address information.

  2. 2

    BUSINESS - update (Main office address)

    Updates the main office address for the business record in the GDB. Ensures both the legal person and business records are kept consistent.

  3. 3

    EXTRACT OF COMPANIES REGISTRY upload

    Generates a PDF Extract of the Companies Registry reflecting the current state of the company after the update, and uploads it to the application record.

If this bot role fails

The file is routed to the PROBLEM Companies update role (system administrator). Common causes and actions:

Likely cause Recommended action
Company ID not found in GDB Verify the Business ID in the application. If correct, contact the database administrator.
Database connection timeout Retry the bot. Usually resolves on its own within a few minutes.
Mapping error A field mapping may be outdated. Contact the system administrator.

Register in ACCOUNTS database

Automated bot role — runs after COMPANIES update succeeds

Step 3

This bot role runs automatically once the COMPANIES database bot role succeeds. It records the annual filing in the ACCOUNTS database and generates the Filing Notice document.

Bots in this role

  1. 1

    ACCOUNTS update

    Updates the filing entries in the ACCOUNTS database. For each fiscal year included in the submission, marks the year as filed and records the filing date. This satisfies the company’s annual report obligation for those years.

  2. 2

    FILING NOTICE upload

    Generates a PDF Filing Notice confirming the annual report has been received and registered, and uploads it to the application record. The citizen can download this notice from their eRegistrations account as proof of filing.

If this bot role fails

The file is routed to the PROBLEM Update accounts role (system administrator). Common causes and actions:

Likely cause Recommended action
Fiscal year not found in ACCOUNTS database Verify the filing year in the application. Check that the year exists in the ACCOUNTS system. Contact the database administrator if missing.
Filing already recorded for this year Check if a duplicate submission was processed. If so, reject the current application and notify the citizen.
Database connection timeout Retry the bot. Usually resolves automatically.
Completion

When this role succeeds, the filing is complete. The application shows FILE VALIDATED on all roles, the fiscal year moves to “Filings Completed” in the citizen’s dashboard, and the Filing Notice is available for download.

5. Assistance

Common Issues

Issue Likely Cause Recommended Action
No filings appear in the citizen’s Filings Due tab ACCOUNTS list bot did not run, or no outstanding filings in the database Ask citizen to reload. If empty, check with database administrator whether filing years are configured for the company.
Application stuck in Review Filing for more than 24 hours No officer has picked up the file Assign to the relevant processing officer or supervisor.
COMPANIES bot failed — company not found Business ID mismatch between eRegistrations and GDB Verify the Business ID in the application against the GDB. Contact database administrator to reconcile.
ACCOUNTS bot failed — duplicate filing Year already recorded in ACCOUNTS database Verify whether a prior filing for the same year exists. If duplicate, reject with explanation.
Filing Notice not generated FILING NOTICE upload bot failed Retry from the PROBLEM Update accounts role. If the issue persists, contact OBFC IT Support.
Citizen cannot see their company in the form Account not linked to the company in vRIGHTS Send back to corrections and ask the citizen to contact the OBFC help desk to have their account linked.
